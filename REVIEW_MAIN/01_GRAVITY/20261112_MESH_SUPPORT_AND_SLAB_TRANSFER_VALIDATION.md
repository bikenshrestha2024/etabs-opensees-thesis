## Critical distinction: fixed point, internal mesh, tied interpolation and reaction output
1. **Original authored ETABS object point:** point geometry identified in the design model. It may have restraints assigned directly by the user or via modeling operations. Count object-level support assignments independently from analysis-point output.
2. **ETABS automatically generated analysis mesh point:** introduced to discretize wall/slab; carries shell nodal DOFs, but does not thereby imply a new soil/foundation support.
3. **Restraint propagation:** CSI ETABS **Wall Auto Mesh Options** has `Add Restraints/Constraints on Edge if Corners have Restraints/Constraints`. When checked, additional edge mesh points inherit restraints/constraints from supported corner joints. The resulting analysis behavior may constrain all base-edge mesh points even though the user assigned restraints to only original ends.
4. **Auto edge constraints:** ETABS may interpolate intermediate edge-joint displacements from master corners. Load on constrained intermediate DOFs can be condensed/reported at master nodes rather than as separate joint reactions. Therefore zero or missing **reported individual ETABS reaction** does not demonstrate an unrestrained free wall-foot node.
5. **OpenSees shell discretization:** `ShellMITC4` is a 3D four-node, six-DOF/node element. Mesh points have genuine displacements and stiffness; OpenSees will not automatically detect ETABS wall auto-mesh or generate CSI interpolation constraints. Current `components/model/assembly.py` creates all 11,097 mesh nodes and shell elements, then uses independent `ops.fix(node, *flags)` for **each exported support tag**.
6. **OpenSees 32 screening:** `ETABS_NONZERO_REACTION_DIAGNOSTIC` releases 44 recorded source-restraint flags and leaves those mesh nodes mechanically free to displace. This is **not** mathematically equivalent to ETABS 32 end support points **plus** interpolation-based constraints, even if both report 32 support reactions.
7. **OpenSees 76 baseline:** all source-export flags applied as independent fixities. This may be an appropriate *analysis-mesh* fixed-base representation if ETABS propagated restraints. But equality of free DOF/connection matrices and reaction reporting against ETABS is still unproven.
8. **OpenSees 97 sensitivity:** 21 additional shell-base mesh nodes independently fixed. Those additional fixities are **not** inferred as actual ETABS support assignments.

### Special case: if the 32 end DOFs are all fixed
For a shell edge whose endpoints have zero displacement and rotation, linear interpolation constraints may force intermediate nodal motion to zero. In that case independent fixities on intermediate analysis nodes may produce the same *kinematic condition*, but the way reactions are aggregated/reported may differ. This is an engineering **hypothesis** requiring exact analysis-mesh topology and constraint-matrix comparison; it is not evidence that the current OpenSees 32 released-node solve is equivalent. Also, OpenSees `equalDOF` or `rigidLink beam` does not generally reproduce CSI multi-master interpolation and could introduce artificial stiffening. Use tested multi-point equations/transformation methods only when exact source constraints are known.

## Official CSI verification note — distributed wall base supports and analysis mesh

CSI's ETABS analysis-reference material distinguishes **object-level joint supports** from automatic internal shell meshing and notes that analysis mesh nodes may optionally take their parent object's restraint conditions. It separately defines joint reactions and explains that support reactions can include tributary effects. Official live help also documents the exact **Wall Auto Mesh Options** checkbox and the **Floor Auto Mesh Options** checkbox for adding edge restraints when corner joints are restrained. The visible 32 original foundation objects can therefore legitimately produce more than 32 restrained *analysis-mesh DOFs*, or their actions may be reported on original joints after constraint condensation. Count modeled foundation supports and counted solver DOFs as different quantities.

The project's exported 76 nodes have assigned ETABS point IDs and six-bit fixed flags; consequently the 44 cannot be dismissed as inconsequential internal mesh nodes **on the supplied evidence**. Conversely an ETABS point ID and a fixed flag do not alone prove a human explicitly drew 44 distinct independent foundation supports. A native object-point vs analysis-mesh classification report is the remaining discriminating evidence, along with the mesh-constraint setting. ## Slab transfer: actual repository method and open physical tests
Inspected `components/model/assembly.py` and `components/gravity/load_path_formulas.py`: every source floor polygon is subdivided into ShellMITC4 cells. Each source uniform slab pressure has its total q*A distributed as `q*A/4` nodal force to **each cell's four OpenSees mesh nodes**; source frame distributed loads are handled separately using consistent beam end vectors. Source self-weight also enters the same load ledger exactly once under validated pattern factors. OpenSees then resolves nodal load through the assembled shell, beams, wall, columns and supports. `rigidDiaphragm(3)` ties UX, UY and RZ, **not UZ**. This does not directly apply ETABS Uniform-to-Frame floor load distribution. Source load type MUST be identified before asserting equivalence.

### Additional geometric defect risk and independent audit
For uniform shell pressure, the *consistent* bilinear quadrilateral nodal vertical load is Fi=integral N_i q dA. The current q*A/4 equal share is **exact for a rectangle/parallelogram**; for a general distorted quadrilateral it need not equal Fi. All floor cells can have the correct overall q*A while individual beam/wall reactions differ. The new **read-only** `tools/audit_shell_gravity_transfer.py` scans the actual exported floor-cell geometry, does 2×2 Gaussian quadrature, reports the count of distorted/invalid cells and the largest differences; it NEVER modifies load vectors.

Before changing physics: verify ETABS source `Uniform (Shell)` versus `Uniform to Frame (Shell)`, source area-load direction and units, shell-to-beam shared nodes, shell-to-wall edge compatibility, floor plate/membrane stiffness and auto edge constraints, diaphragm assignment, base support mechanics and original per-storey load pattern.
