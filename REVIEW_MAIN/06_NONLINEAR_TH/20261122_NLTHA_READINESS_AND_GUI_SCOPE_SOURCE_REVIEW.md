## Screenshot diagnosis: original 20 blockers are an expected preflight refusal

The GUI's `_require_nonlinear_readiness` denied execution *before calling a native OpenSees solver*. The original error included exactly 20 items: 16 `check_false:...` engineering checklist reviews, `not_approved` and three model options `material_file_missing`, `wall_fsam_tags_empty`, `parameters_not_reviewed`. A successful preceding ELASTIC ULS modal/MRSM run cannot prove nonlinear beam rebar/ConcreteCM/FSAM wall web-confinement calibration, diaphragm connection, source ground motions or selected FVD/BRB case approval. Zero-duration `trial_duration_s=0` requests full records but does **not** waive the model gate.

**Root-cause UI issue:** `_run` caught the 20-item `RuntimeError` at its outer `except` and sent its entire contents to the small `messagebox.showerror`, producing the nearly unreadable modal box shown by the user. **Corrected route:** if the preflight denies a run, the GUI opens a separate scrollable, source-grouped readiness dialog with complete raw codes/fixes, a link to the bound readiness editor, copy and explicit local text-save actions. The old production gate still runs first and still blocks; the tool does **not** mark any reviewer approval True.

**Root-cause output classification issue:** `_run` previously defined `scope='Trial' if trial_duration_s is not None`; since the GUI always constructs a numeric `trial_duration_s` (0.0 for full records), full-length production requests were mislabeled as `Trial`. Now `_nltha_output_scope` chooses Suite only for a truly full record (`None` or 0) unless an explicit preliminary selection is on; a positive truncated history remains Trial. Scope labels do not supersede the downstream saved full-accepted-history and engineering acceptance gates.
