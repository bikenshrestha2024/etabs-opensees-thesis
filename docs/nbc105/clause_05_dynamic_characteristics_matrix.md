## Call sites routed through the module

`components/modal/analysis.py` (`nbc105_period_estimate`), `components/modal/rayleigh.py` (empirical and amplified values in the Rayleigh audit and workbook), `components/inputs/analysis_autofill.py` (`workbook_adopted_period`), `components/equivalent_static/calculation_and_gui.py` (four sites; tkinter code checked with `python -m py_compile` only), `components/inputs/grouped_wall_aw.py` (single-wall factor). The response-spectrum period defaults reach the module through `nbc105_period_estimate`.

## Production routing of the module

Production-routed: `empirical_period_s`, `amplified_period_s`, `period_factor_deviation` (analysis.py, rayleigh.py, analysis_autofill.py, calculation_and_gui.py), `effective_wall_area_m2` (grouped_wall_aw.py only), `storey_index_for_elevation` (assembly.py). Reference implementations with unit tests but no production caller: `adopted_period_s`, `rayleigh_period_s`, `building_height_m`, `seismic_weight_kN`. Their rules are applied inline at the call sites, so the module is not a single source of truth for those rules.

## Open items

- Basement (rows 6 and 14): USER_DECLARED 2026-11-21, the structure has no basement, so H is the full height from the base to the roof and the Figure 5-1 exclusion is not applicable. `analysis_autofill.py` takes H = max node z - `base_z_m`, so `base_z_m` must be the base level. Not verified by the agent. See [project declarations](PROJECT_DECLARATIONS.md) item 1.
- Wall grouping (row 15): USER_DECLARED 2026-11-21, the grouping of Aw was validated by the user against UBC and SEAOC references; `REFERENCE DETAILS PENDING FROM USER` for edition and section. NBC 105:2025 does not define grouping around openings. Not verified by the agent, and every Aw result stays `code_accepted: false`. See [WALL_GROUPING_AW_METHOD.md](WALL_GROUPING_AW_METHOD.md) and [project declarations](PROJECT_DECLARATIONS.md) item 2.
- g: USER_DECISION, resolved on 2026-11-21 (recorded as USER_DECLARED, not verified by the agent). NBC 105:2025 notation list (printed p. 7) says g = 9.81 m/s^2; the project uses `components.nbc105.constants.GRAVITY_M_S2` = 9.80665 m/s^2 everywhere weight and mass are converted (Eq. 5.1(1) in `rayleigh.py` and `rayleigh_period_s`, `assembly.py`, and the audit and review helpers listed in the [constants guide](../source/components/nbc105/constants.py.md)). Difference 0.0341 % (9.81/9.80665 = 1.000342); Rayleigh T changes by about +0.017 % (sqrt of the ratio); the assembly weight/mass conversion already used 9.80665 and is numerically unchanged. `NBC_NOTATION_GRAVITY_M_S2` = 9.81 is kept as a reference value only.
- Floating-point: at factor 1.25 the module's operation order differs from the previous inline `.075*H**.75/sqrt(Aw)` by up to 1 ulp.
